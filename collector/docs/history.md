# Historical backfill

Historical collection has its own checkpoints. It never moves the live collection horizon or replaces an existing complete canonical message with an older copy. Source exclusions still win. All account coverage remains partial.

From `collector/`, run `python history_collect.py --config /absolute/private/runtime/collector.json --once`. Each local pass reads at most 16 MiB of payload and resumes a private file queue. `--watch` repeats headlessly. `history/STOP` pauses history without stopping live collection. Undated, uncertain-origin and unsupported records do not become diary evidence.

For native ChatGPT, the existing app agent saves exact decoded native JSON privately. Use `native_chatgpt_history.py --config ABS --active FILE` for schema 4 metadata and `--archive FILE [--cursor CURSOR]` for exact archived metadata. `--plan` returns at most five page reads. Read each planned chat with the exact returned cursor, ten turns, outputs disabled and 20,000 characters per item. Save schema 1 JSON and pass `--page FILE --thread ID [--cursor CURSOR]`. This helper imports through the historical preservation policy and advances only its own frontier after an actual Store receipt. It never acknowledges the recent planner. Three failed pages become explicit gaps. Native source STOP, native history STOP and universal history STOP all apply. The active list currently exposes only a recent mixed slice, so account completeness cannot be inferred; archived listing has its own end cursor.

The hidden Claude `backfill.cjs` runner accepts bounded `start_offset`, `page_size` and `max_pages` inventory settings. It binds the existing authenticated profile to an expected source, uses profile locks, and has no show/focus/login path. Its ingestion is historical. Do not run it concurrently with the live bridge. A bounded maintenance pass may stop the owned collector, inspect the exact existing STOP it created, and restore the collector in a `finally` block; never clear a user-created STOP or replace credentials. Inventory EOF does not prove every chat body is supported.

On the work Mac, `macos/history_install.py` installs a separate disabled-first coordinator using the existing controlled producer and on-device model. The coordinator handles current/previous dates first, then older dates, preserving raw collection, queues and controlled ledgers. Installation requires verified current-user ownership, pinned source, portable tests and a real controlled handoff. Only finite-language descriptions cross to the private journal. Large records and the 32-moment daily capacity are explicit gaps. The old producer must be upgraded with the same reviewed source before history starts, so both understand the shared ledger and omission sidecar.

Before historical writing, run `discover_work_history.py --config /absolute/private/runtime/personal-summary.json --once`. It verifies the private destination and validates at most twenty changed controlled handoff files, including exact Git blob hashes. It writes `narrative-history/validated-work-days.json`. Pass that file to `narrative_history_plan.py --config ABS --plan --work-days FILE` so dates containing only work evidence are included. Invalid or unavailable handoffs never establish journal facts.

Follow [the native writer runbook](narrative-writer.md) for two historical dates per pass, factual review, protected append-only publication and receipt-bound acknowledgments. A prepared input is not a written entry. Before creating an absent historical entry, check exact-path commit metadata for deletion intent; never resurrect a removed entry or download old work blobs. Keep all evidence, candidates and checkpoints outside this checkout.
